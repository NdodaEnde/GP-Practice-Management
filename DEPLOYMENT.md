# SurgiScan — Production launch runbook (Essential / digitisation tier)

Scope locked for v1: **concierge onboarding · Essential tier only · manual
billing · RLS on before launch.** This runbook gets a fresh production
environment live and ready to onboard the first paying practice.

Steps marked **[YOU]** require your secrets / prod access / the migration
gate — I do not run these for you. Steps are ordered; don't skip ahead.

---

## 0. Prerequisites
- A fresh **PROD Supabase project** (Pro plan) — empty.
- Render account (backend) + Netlify account (frontend), or all-Render.
- `pg_dump` + `psql` locally (`brew install libpq && brew link --force libpq`).
- The DEV project is the source of truth for schema + reference data.

## 1. Bootstrap the PROD database  **[YOU]**
The migrations folder is NOT a from-zero schema — do **not** run
`production_bootstrap.sql`. Use the dump script (it copies schema + indexes +
functions + **RLS** + reference data: ICD-10 / NAPPI / product catalog — and
**no** patient or demo data):

```bash
DEV="postgresql://postgres.<DEVREF>:<DEVPASS>@aws-0-<REGION>.pooler.supabase.com:5432/postgres" \
PROD="postgresql://postgres.<PRODREF>:<PRODPASS>@aws-0-<REGION>.pooler.supabase.com:5432/postgres" \
bash backend/scripts/migrate_dev_to_prod.sh
```

Because RLS migration **033** was applied to DEV, the dump carries **complete
RLS** (all tenant/PHI tables deny-all to non-service) into prod automatically.

**Verify on PROD** (psql against the PROD string):
```sql
-- RLS must be ON for tenant tables (expect t for all)
SELECT relname, relrowsecurity FROM pg_class c JOIN pg_namespace n ON n.oid=c.relnamespace
WHERE n.nspname='public' AND relname IN
 ('patients','digitised_documents','gp_validation_sessions','lab_results','prescription_items');
-- catalog must be present (expect module_digitisation row)
SELECT id FROM products WHERE id='module_digitisation';
-- NO patient/clinical data should have come across (expect 0)
SELECT count(*) FROM patients;  SELECT count(*) FROM digitised_documents;
```

## 2. Create PROD Storage buckets (PRIVATE)  **[YOU]**
The DB dump does **not** copy Storage. In the PROD Supabase dashboard →
Storage, create both buckets as **private** (no public access — the backend
serves files via short-lived signed URLs):
- `medical-records`  (uploaded scans / PDFs)
- `digitisation-exports`  (generated FHIR/CSV bundles)

## 3. Deploy the backend (Render)  **[YOU]**
`backend/render.yaml` + `backend/Dockerfile` are production-correct
(entrypoint `server:app`, healthcheck `/api/health`, binds `$PORT`).
Create the service from the blueprint (root dir `backend/`) and set these
secrets in the Render dashboard:

| Var | Value |
|---|---|
| `JWT_SECRET_KEY` | auto-generated by Render (leave it) |
| `DEBUG` | `false` (already in yaml — also hides API docs + arms the JWT guard) |
| `SUPABASE_URL` | PROD project URL |
| `SUPABASE_SERVICE_KEY` | PROD service-role key (secret) |
| `DATABASE_URL` | PROD Postgres (session pooler) string |
| `OPENAI_API_KEY` | for semantic search |
| `LANDING_AI_API_KEY` + `VISION_AGENT_API_KEY` | for document extraction |
| `CORS_ORIGINS` | set in step 5 (the frontend origin) |

Deploy → confirm `GET https://<backend>/api/health` returns
`{"status":"healthy","database":"connected", ...}`.

## 4. Deploy the frontend (Netlify)  **[YOU]**
`netlify.toml` (repo root) sets base `frontend`, `npm ci && npm run build`,
publish `frontend/build`, and the SPA rewrite. In the Netlify dashboard set
the build env var:
- `REACT_APP_BACKEND_URL = https://<backend>.onrender.com`  (baked at build)

Deploy → note the frontend URL (e.g. `https://app.surgiscan.co.za`).
*(All-Render alternative: a Render Static Site with the same build cmd /
publish dir / `/* -> /index.html` rewrite.)*

## 5. Wire CORS  **[YOU]**
Set the backend's `CORS_ORIGINS` to the **exact** frontend origin(s) from
step 4 (comma-separated, no trailing slash) and redeploy the backend.

## 6. Pre-launch verification  **[YOU + me]**
- [ ] `/api/health` green; `/docs` and `/openapi.json` return 404 (DEBUG off).
- [ ] Login works end-to-end from the deployed frontend.
- [ ] **Cross-tenant probe vs PROD** — point `backend/.env` at PROD and run the
      synthetic two-tenant probe (same one used on DEV) to confirm isolation
      holds with prod data/RLS. (Ask me — I have the probe ready.)
- [ ] Storage buckets confirmed **private** (an unauthenticated fetch of an
      object path 404/403s; only signed URLs work).
- [ ] RLS spot-check (step 1 query) shows `t` for tenant tables.

## 7. Onboard the first practice  **[YOU]**
With `backend/.env` pointed at **PROD**:
```bash
PYTHONPATH=. ./.venv/bin/python scripts/onboard_practice.py \
  --practice "Their Practice Name" --email admin@their.co.za --name "Their Admin"
```
See `backend/scripts/ONBOARDING_RUNBOOK.md`. Send them the printed email +
password. Done — they can log in and start digitising.

## Rollback / safety notes
- Backend `autoDeploy: false` — deploys only on explicit trigger.
- RLS is reversible per table (`ALTER TABLE x DISABLE ROW LEVEL SECURITY`).
- Billing is `manual` — no gateway to fail; suspend a practice by setting its
  entitlement `status='paused'`.
- Keep the DEV project as-is; prod is a separate project. Never point a deploy
  at DEV.
